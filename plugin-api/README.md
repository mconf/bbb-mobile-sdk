# Mobile plugin API

The contract between the plugin host of the BigBlueButton mobile SDK and its plugins:

- the types of the host (`MobilePluginHost`), of a plugin (`MobilePluginDefinition`) and of
  the items the host draws for a plugin (selector rows, dialogs, notices);
- `definePlugin`, which declares a plugin;
- a mock host for plugin unit tests, under `@mconf/bbb-mobile-plugin-api/testing`.

This folder is its own npm package, with its own dependencies and lockfile. The app does not
import it yet, and it is not part of the app's install, build, lint or type-check.

## Status and versioning

The version is `0.x`. **There is no compatibility promise before 1.0: any 0.x release may
break plugins.**

Each plugin declares the host API versions it works with in `requiredHostApi`, as a semver
range in npm's grammar (caret, tilde, x-ranges, exact versions, `||`). The host compares the
range with its own version when it loads the plugin, and skips and logs a plugin that does
not match. npm's pre-release rule applies: a pre-release host version satisfies only a range
that names a pre-release of the same `major.minor.patch`. The check itself is host code and
is not in this package.

The version is in two places that must agree: `version` in `package.json` and
`HOST_API_VERSION` in `src/version.ts`.

## Using it from a plugin

The package is not published to npm. Build a tarball from a commit of this repository and
install the file:

```bash
cd plugin-api
npm ci
npm pack        # builds dist/ and writes mconf-bbb-mobile-plugin-api-<version>.tgz
```

```bash
# in the plugin
npm install --save-dev /path/to/mconf-bbb-mobile-plugin-api-<version>.tgz
```

Record the commit the tarball was built from. During development, build the tarball from a
local checkout the same way. Do not depend on the folder itself (`file:` to the folder): npm
links it, and the folder's own `node_modules` brings a second copy of React, so hooks fail
with "Invalid hook call".

```ts
import { definePlugin } from '@mconf/bbb-mobile-plugin-api';

export default definePlugin({
  name: 'example-plugin',
  requiredHostApi: '^0.1.0',
  create(host) {
    const Headless = () => {
      const locale = host.useLocale();
      // ...
      return null;
    };
    return { Headless };
  },
});
```

```ts
import { createMockHost } from '@mconf/bbb-mobile-plugin-api/testing';

const { host, controller } = createMockHost();
```

`react` is a peer dependency. The package is ES modules only: a test runner that loads it
as CommonJS (such as Jest without a transform for this package) cannot import it. Its types
import React's, so a TypeScript plugin also needs `@types/react`. Both entries resolve under
the `moduleResolution` settings `node` and `bundler`, and under `node16` and `nodenext` from
an ES module.

## Working on the contract

Use the Node version in the repository's `.nvmrc`.

| Command | What it does |
|---|---|
| `npm ci` | Installs this folder's dependencies. |
| `npm test` | Runs the unit tests and the conformance cases against the mock host. |
| `npm run typecheck` | Type-checks `src/` and `test/`. |
| `npm run build` | Writes `dist/`. |
| `npm run api:check` | Builds, then checks the API reports and the version rule. |
| `npm run api:update` | Builds, then rewrites the API reports in `etc/`. |

### API reports

`etc/plugin-api.api.md` and `etc/plugin-api-testing.api.md` list everything the package
exports. They are generated by API Extractor and committed.

`npm run api:check` fails when:

1. `HOST_API_VERSION` differs from the version in `package.json`;
2. a report differs from what the build produces (run `npm run api:update`);
3. a report differs from the base branch and the minor version is not higher than there.

So a change to a report needs a higher minor version; a change that leaves the reports alone
needs at most a higher patch version. The base branch is `origin/mobile-plugins/trunk`; set
`API_BASE_REF` to compare with another ref.

A pull request that changes the contract includes the report diff and pastes the output of
`npm run api:check`.

### Conformance cases

`test/conformance/suite.ts` holds the cases every host must pass. Today they run against the
mock host. A case that needs host code that does not exist yet is an `it.todo`; it becomes a
test in the pull request that adds that code.
